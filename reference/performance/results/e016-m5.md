# E016 Apple M5 confirmation

Date: 2026-08-06  
Environment: Apple M5, macOS, JDK 25.0.4 Temurin, NEON 128-bit,
`IntVector.SPECIES_PREFERRED` = four int lanes.

## Correctness

Command:

```text
JAVA_TOOL_OPTIONS=-Dfastblake.experimental.scratchChunkVector=true \
  ./gradlew test --rerun-tasks
```

Result: full conformance suite passed with Commons, Rust and Java contenders
present. This covers ordinary hash, keyed hash, derive-key, XOF, reset, repeated
finalization, input/output offsets and incremental boundaries through 102,400
bytes. The large cases execute the pending-buffer SIMD branch.

## E016 scratch-vector throughput

Command:

```text
JAVA_TOOL_OPTIONS=-Dfastblake.experimental.scratchChunkVector=true \
  ./gradlew jmh \
  -P'jmh.args=Blake3Benchmark -p impl=java-cpu -p size=8388608 -f1 -wi 3 -i 3'
```

| 8 MiB shape | average time | throughput |
|---|---:|---:|
| one-shot | 4,654,915.998 ns/op | 1719 MiB/s |
| reused | 4,538,706.706 ns/op | 1763 MiB/s |
| streaming 4 KiB | 4,633,815.029 ns/op | 1726 MiB/s |

The one-shot average included one slow measurement. A longer isolated rerun,
five warmup and five measurement iterations, produced 4,548,705.656 ns/op or
1759 MiB/s with a 4,567 ns standard deviation.

Recorded pre-E016 E011+E014 M5 control: 1750 MiB/s one-shot, 1769 MiB/s reused,
907 MiB/s streaming. Using the stable one-shot rerun, E016 changes the three
shapes by +0.5%, -0.3% and approximately +90%. Contiguous changes are far inside
the 3% inconclusive band; streaming is a decisive improvement.

## Allocation gate

Command:

```text
JAVA_TOOL_OPTIONS=-Dfastblake.experimental.scratchChunkVector=true \
  ./gradlew jmh \
  -P'jmh.args=Blake3Benchmark -p impl=java-cpu -p size=8388608 \
  -f1 -wi 3 -i 3 -prof gc'
```

| shape | time | B/op | B/input byte | collections |
|---|---:|---:|---:|---:|
| one-shot | 4,549,915.033 ns | 12,455.674 | 0.001485 | 0 |
| reused | 4,551,295.107 ns | 4,751.675 | 0.000566 | 0 |
| streaming 4 KiB | 4,656,527.988 ns | 4,752.458 | 0.000567 | 0 |

The larger one-shot value includes hasher construction and its 4096-byte pending
buffer. Allocation is fixed per operation rather than proportional to input.

## Production scalar VarHandle check

Command:

```text
./gradlew jmh \
  -P'jmh.args=Blake3Benchmark -p impl=java-cpu -p size=8388608 -f1 -wi 3 -i 3'
```

| 8 MiB shape | E016 scalar | earlier E009 M5 quick run | change |
|---|---:|---:|---:|
| one-shot | 923 MiB/s | 894 MiB/s | +3.2% |
| reused | 919 MiB/s | 883 MiB/s | +4.1% |
| streaming 4 KiB | 921 MiB/s | 874 MiB/s | +5.4% |

These are non-simultaneous quick-run comparisons, so they support the direction
of the VarHandle improvement but are not a substitute for a checkout-paired
factorial run.

## Decision

E016 passes on the M5. Retain the pending buffer in the opt-in
`scratchChunkVector` path and retain the scalar VarHandle loader. There is no
measured contiguous-input regression on this CPU, while 4 KiB streaming is now
in the same performance class as one-shot and reuse. Automatic promotion still
needs the planned longer multi-fork comparison and another AVX2 CPU profile.
