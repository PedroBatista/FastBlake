# E017 Intel N97 kernel decomposition

Date: 2026-08-06  
Environment: Intel N97, Linux, custom OpenJDK 28-internal with hdis, AVX2,
Rust 1.97.1 and `blake3` 1.8.5.

## M5 prerequisite

Commit `53fdca0` supplies the E016 Apple M5 confirmation. The scratch-vector
path measures 1759/1763/1726 MiB/s for one-shot/reused/streaming 4 KiB, so the
pending buffer fixes streaming without a measurable contiguous regression.
E017 therefore targets the remaining contiguous N97 kernel gap.

## Hardware counters

The machine owner temporarily changed `kernel.perf_event_paranoid` from 4 to 2,
enabling unprivileged user-space counters. JMH's `perfnorm` profiler reports
events per completed 8 MiB hash. The run used CPU 3, three forks, 5x1 s warmup
and 5x1 s measurement:

| counter per 8 MiB hash | Java SIMD | Rust AVX2 | Java / Rust |
|---|---:|---:|---:|
| time | 10,040,406 ns | 4,975,239 ns | 2.02x |
| cycles | 29,750,681 | 14,660,987 | 2.03x |
| instructions | 89,831,081 | 20,989,782 | **4.28x** |
| IPC | **3.019** | 1.432 | 2.11x |
| branches | 5,355,545 | 87,154 | **61.45x** |
| branch misses | 6,157 | 349 | 17.63x |
| cache references | 173,933 | 150,681 | 1.15x |
| cache misses | 130,534 | 113,850 | 1.15x |

Normalized per input byte, Java uses 3.547 cycles, 10.709 instructions and
0.638 branches; Rust uses 1.748 cycles, 2.502 instructions and 0.0104 branches.
Java's branch miss rate is only 0.115% versus Rust's 0.401%. The generic cache
events are close in absolute count and cannot explain a twofold time gap.

This changes the diagnosis. Java does not lose because the N97 cannot keep its
pipeline busy: it retires 3.02 instructions/cycle, more than twice Rust's IPC.
It loses because C2 asks the core to execute 4.28 times as many instructions.
Java's higher IPC recovers roughly half of that excess, leaving the measured
2.03x cycle gap. Reducing instruction and branch volume is the primary target;
adding explicit state loads/stores attacks the wrong mechanism.

Reproduction while counter access is enabled:

```text
taskset -c 3 perf stat -r 5 \
  -e cycles,instructions,branches,branch-misses,cache-references,cache-misses \
  <the focused JDK 28 JMH command, once with impl=java-cpu and once with impl=rust>
```

The actual run used JMH's operation-normalized equivalent:

```text
-prof perfnorm:events=cycles,instructions,branches,branch-misses,cache-references,cache-misses
```

Raw result: `build/jmh-jdk28-e017-counters.json`. Restore the machine's previous
`perf_event_paranoid` value after collection.

## Exact phase probes

`ChunkVectorKernelBenchmark` invokes the actual
`Blake3ChunkVectorScratch.hashChunks` entry point and reproduces its exact
lane-by-lane CV extraction. The existing E014 transpose and E011 compact-round
probes supply the current one-block load and compression phases. One fork,
5x1 s warmup, 5x1 s measurement, `-prof gc`:

| phase | cost | scaled four-chunk batch cost | share of estimate |
|---|---:|---:|---:|
| VarHandle load/transpose, one block | 24.201 ns | 387.216 ns | 9.2% |
| seven compression rounds, one block | 239.100 ns | 3825.600 ns | 90.5% |
| four-CV lane extraction | 17.113 ns | 17.113 ns | 0.4% |
| phase sum | — | 4229.929 ns | 100% |
| exact complete four-chunk kernel | — | 4225.706 ns | — |

The independently measured sum differs from the complete kernel by only 0.1%,
which validates the decomposition at this resolution. Every phase allocates
effectively zero. Loader and extraction work together account for less than
10% of time, so neither can materially close the twofold Rust gap. Compression
is the only credible target.

Raw result: `build/jmh-jdk28-e017-phases.json`.

With counters enabled, the exact complete batch retires 37,620 instructions,
12,190 cycles and 2,485 branches. The separately compiled phase controls give:

| phase | instructions | cycles | branches |
|---|---:|---:|---:|
| load/transpose, one block | 311.8 | 67.7 | 34.0 |
| seven rounds, one block | 1,988.6 | 716.2 | 139.3 |
| extraction, one batch | 124.3 | 49.0 | 5.0 |

Sixteen load and compression phases plus extraction predict 36,931
instructions and 12,591 cycles, respectively within 1.8% and 3.3% of the exact
complete-batch counters. Compression contributes about 31,817 instructions
before whole-kernel context effects, confirming it as both the time and
instruction-count target. Raw result:
`build/jmh-jdk28-e017-phase-counters.json`.

## Core-pinned Java/Rust control

A three-fork run pinned the parent and all JMH children to CPU 3. Each fork used
5x1 s warmup and 5x1 s measurement on the same 8 MiB input:

| implementation | average | throughput |
|---|---:|---:|
| Java E016 scratch vector | 9,989,643.357 ns/op | 801 MiB/s |
| Rust AVX2 | 5,002,774.336 ns/op | 1599 MiB/s |

The pinned Java path is 50.1% of Rust. This agrees with the earlier quick-run
ratio while reducing scheduling ambiguity. Raw result:
`build/jmh-jdk28-e017-pinned.json`.

## Smaller-live-set prototype

The bounded prototype stores all 16 state vectors in reusable primitive
scratch and materializes only one G's four state vectors and two messages at a
time. A constructor assertion compares all four lanes after seven rounds with
a scalar reference. The prototype is retained only in JMH code.

| seven-round shape | cost | allocation | change |
|---|---:|---:|---:|
| current named-vector loop | 247.129 ns | 0.002 B/op | control |
| state-scratch G boundary | 387.569 ns | 0.002 B/op | **+56.8% time** |

hdis shows why the nominally smaller live set loses: C2 keeps `g` as a separate
1344-byte compiled method with a 112-byte frame, repeated range checks, four
state-vector loads, two message loads and four state-vector stores per call.
The caller invokes that boundary 56 times per block. Explicit memory traffic
and call/check overhead cost more than the current kernel's spill strategy.

Decision: reject state scratch for production; retain it as an allocation-free
negative control. Do not spend another experiment on loaders, CV extraction,
or Java-level state parking. Counters show that the current Java path has good
IPC and approximately Rust-like cache-event volume, but executes 4.28x the
instructions and 61x the branches. The next productive fork must remove work:
quantify loop/range-check and spill instructions in the compact round body,
then test partial unrolling below the known seven-round escape-analysis cliff.
The byte-aligned rotate gap is real but accounts for only part of the excess;
a HotSpot rotate intrinsic/compiler fix remains preferable to wrapper-heavy
shuffle expressions.

Raw result: `build/jmh-jdk28-e017-low-live.json`.
